# โค้ดที่ต้องตรวจ — งานข้อ ① ของแล็บสัปดาห์ที่ 12

โฟลเดอร์นี้มีโค้ดสี่ชิ้นจาก **แอปส่งอาหารตัวหนึ่งที่ทำฟีเจอร์เดียวกันกับที่คุณกำลังจะทำ** คือ
อ่านตำแหน่งของผู้ใช้มาแสดงเป็นที่อยู่ปลายทาง และถ่ายรูปจากในแอป

**อ่านสามบรรทัดนี้ก่อน มันเปลี่ยนวิธีทำงานของคุณทั้งข้อ**

1. **โค้ดชุดนี้คอมไพล์ผ่าน รันขึ้น และทำงานได้ตามที่ผู้เขียนตั้งใจ** — ไม่ใช่โค้ดที่พัง
   ไม่มี error ให้แก้ · เครื่องไม่บอกว่ามีอะไรผิด · `flutter analyze` ก็ไม่บอก
2. งานของคุณคือหาว่ามันขัดกับ **กฎของแพลตฟอร์มและเอกสารทางการ** ตรงไหน — คนละเรื่องกับ
   การหาบั๊ก · ของที่คุณต้องหาคือสิ่งที่ *ทำงานได้* แต่ *ไม่ควรทำ*
3. **ห้ามแก้ไฟล์ในโฟลเดอร์นี้** เขียนสิ่งที่พบลง `AUDIT.md` ของคุณเอง

## ไฟล์ในโฟลเดอร์

| ไฟล์ | ยกมาจาก | ในโปรเจคเดิมทำหน้าที่อะไร |
|---|---|---|
| `AndroidManifest-excerpt.xml` | `android/app/src/main/AndroidManifest.xml` | ประกาศสิทธิ์ที่แอปนี้ขอ |
| `pubspec-excerpt.yaml` | `pubspec.yaml` บล็อก `dependencies` | แพ็กเกจที่แอปนี้ใช้ พร้อมรุ่นที่ล็อกไว้ |
| `home_screen-excerpt.dart` | `lib/screens/home/home.dart` | หน้าแรก — อ่านตำแหน่งมาแสดงบนแถบหัวจอว่า "Deliver to ..." |
| `profile_body-excerpt.dart` | `lib/screens/profile/profile_body.dart` | หน้าตั้งค่าบัญชี — ถ่ายรูปโปรไฟล์ |

โค้ดในไฟล์ `.dart` **ยกมาทั้งบล็อกโดยไม่แก้แม้ตัวอักษรเดียว** รวมทั้งช่องว่างท้ายบรรทัดและ
การตั้งชื่อเมธอด · ส่วนที่ตัดออกมีสองอย่างเท่านั้น คือ `import` ของชิ้นส่วนหน้าตาที่ไม่เกี่ยวกับสิทธิ์
และเมธอด `build()` · ตำแหน่งที่ตัดเขียนกำกับไว้ในไฟล์แล้ว

ชื่อแพ็กเกจของโปรเจคเดิมถูกเปลี่ยนเป็น `food_order` — **ไม่ต้องไปหาว่าโปรเจคเดิมคืออะไร
มันไม่ได้อยู่ในที่ที่เปิดได้ และไม่มีคะแนนให้กับการไปหา**

## ขอบเขตที่ถือว่าจริง — ใช้สรุปได้เลย ไม่ต้องสงสัย

สี่ไฟล์นี้คัดมาจากโปรเจคที่มีไฟล์เยอะกว่านี้มาก ข้อความสามข้อข้างล่างจึงเขียนไว้ให้
**เพื่อให้คุณสรุปได้โดยไม่ต้องเห็นโปรเจคทั้งก้อน** — ผู้จัดทำค้นในโปรเจคต้นฉบับทั้งโฟลเดอร์แล้ว

1. **โค้ดทุกบรรทัดที่เกี่ยวกับการขอสิทธิ์ในโปรเจคนั้น อยู่ในสองไฟล์ `.dart` นี้ครบแล้ว**
   ไม่มีไฟล์อื่นที่ขอสิทธิ์
2. **บล็อกสิทธิ์ใน `AndroidManifest-excerpt.xml` คือทั้งหมดที่ไฟล์จริงประกาศไว้** ไม่มีบรรทัด
   `uses-permission` อื่นที่ถูกตัดออก
3. **`pubspec-excerpt.yaml` คือบล็อก `dependencies` ทั้งบล็อก** ยกมาตามลำดับจริง ไม่ได้ตัดรายการใดออก

ข้อ 1 สำคัญที่สุด เพราะมันทำให้คุณสรุปได้ว่า **แพ็กเกจใดใน `pubspec` ที่ไม่มีโค้ดเรียกใช้เลย**
— ซึ่งเป็นข้อค้นพบที่หาไม่ได้ถ้าอ่านแค่ไฟล์ `.dart`

## สิ่งที่นับว่าเป็นข้อค้นพบ

ข้อค้นพบที่ใช้คะแนนได้ต้องตอบได้ทั้งสามช่อง

1. **ชี้ได้ว่าอยู่บรรทัดไหนของไฟล์ไหน** (เขียนเลขบรรทัดของไฟล์ในโฟลเดอร์นี้)
2. **บอกได้ว่าขัดกับอะไร** — อ้างเอกสารทางการหรือหลักที่เรียนในคาบ พร้อมชื่อเรื่องที่อ้าง
3. **บอกได้ว่าผลกับผู้ใช้จริงคืออะไร** — ผู้ใช้เจออะไรที่ไม่ควรเจอ หรือข้อมูลอะไรไปอยู่ที่ไม่ควรอยู่

ข้อที่เขียนว่า "โค้ดไม่สวย" "ควรแยกไฟล์" "ตั้งชื่อไม่ดี" **ไม่นับ** — ไม่ใช่เพราะผิด แต่เพราะ
ไม่ใช่เรื่องของแล็บนี้

## ข้อค้นพบสองประเภทที่ต้องแยกให้ออก

โค้ดชุดนี้มีทั้งสองประเภท และใบตรวจของคุณต้องระบุว่าแต่ละข้อเป็นประเภทใด

- **ประเภท ก — ผิดกฎของแพลตฟอร์มหรือของร้านค้า** เช่น ขอสิทธิ์ที่ไม่มีฟีเจอร์ใดใช้
  ผลที่ตามมาเกิดกับทีมผู้พัฒนา (ส่งขึ้นร้านค้าไม่ผ่าน ต้องชี้แจง)
- **ประเภท ข — ผิดต่อผู้ใช้** เช่น ผู้ใช้ถูกพาไปหน้าตั้งค่าโดยไม่ได้ขอ
  หรือข้อมูลของผู้ใช้ถูกส่งไปที่ที่ผู้ใช้ไม่รู้ ผลที่ตามมาเกิดกับผู้ใช้

บางข้อเป็นทั้งสองประเภท เขียนว่าเป็นทั้งสองได้ ถ้าอธิบายได้ว่าเพราะอะไร
